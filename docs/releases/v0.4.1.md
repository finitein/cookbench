# Cookbench v0.4.1

Cookbench v0.4.1 is a stability-first safety hotfix for macOS. It keeps the
Minimal Bar and top-docking features from v0.4.0 while restoring the proven
static tray path used by v0.3.0.

## What Changed

- **Dynamic macOS status Stoves are temporarily suspended.** A v0.4.0 launch
  on mirrored dual displays was followed by a WindowServer render-server stack
  overflow. The dynamic native status image, menu rebuild, click mapping, and
  snapshot refresh path are therefore disconnected in this release.
- **The static tray remains.** Cookbench still provides its ordinary tray icon
  and localized menu without changing that icon from incoming Stove snapshots.
- **Preferences are preserved.** The saved zero-to-eight status Stove count
  (default three) remains in persisted configuration, but the setting is hidden
  while the native presentation is unavailable.
- **Window minimum-size updates now converge.** Repeated identical native size
  requests are deduplicated, and dock geometry refreshes only while the Bar is
  actually docked.

## Install

v0.4.1 remains an unsigned prerelease and must be selected explicitly:

```bash
curl -fsSL https://github.com/finitein/cookbench/releases/download/v0.4.1/install.sh | COOKBENCH_VERSION=v0.4.1 COOKBENCH_ALLOW_PRERELEASE=1 bash
```

```powershell
$env:COOKBENCH_VERSION='v0.4.1'; $env:COOKBENCH_ALLOW_PRERELEASE='1'; irm https://github.com/finitein/cookbench/releases/download/v0.4.1/install.ps1 | iex
```

## Safety And Verification

The crash report records recursive Core Animation fence resolution in
WindowServer shortly after Cookbench's dynamic status item appeared. v0.3.0
worked on the same Mac and mirrored-display setup, so v0.4.1 removes the new
native status mutation path rather than attempting to tune it in production.

Automated verification intentionally does not launch Cookbench on the affected
Mac. The release is checked through source-level regression tests, Rust and
TypeScript tests, builds, package audits, and CI packaging. A future dynamic
status implementation requires isolated native testing across mirrored,
extended, single-display, Retina, and constrained menu-bar configurations
before it can be enabled again.
