# Cookbench v0.3.0

Cookbench v0.3.0 turns the preview into a much more complete local-first
workbench for parallel coding-agent sessions. It expands the adapter catalog,
strengthens session-to-window identity, adds real lifecycle management, and
polishes the desktop surfaces without turning Cookbench into an agent control
plane.

> This is an **unsigned prerelease**. The packages are produced by the public
> GitHub Actions workflow and published with `SHA256SUMS` plus a machine-readable
> release manifest, but they are not yet Apple-notarized or Windows-signed.

## Highlights

- **27 honest Harness profiles.** Full, Standard, and Experimental tiers now
  cover Codex, Claude Code, Pi, Gemini CLI, Qwen Code, Kimi Code, Qoder, ZCode,
  Cursor, Cline, CodeBuddy, Tencent WorkBuddy, and many more. Capability and
  fallback differences remain visible instead of being flattened into one
  unsupported promise.
- **Automatic native discovery.** Leave Session roots empty and Cookbench scans
  the standard native roots for Codex, Claude Code, and Pi. Other catalog
  profiles use their documented Hook, manual, or presence path; explicit
  absolute roots remain available for nonstandard layouts.
- **Cookbench-owned Hook health.** Codex, Claude Code, Pi, Kimi Code, and ZCode
  Hooks can be previewed, installed, checked, repaired, and removed while
  preserving unrelated Harness configuration.
- **Stronger exact return.** Verified process, terminal, and IDE identity links
  are preferred. Codex Desktop uses guarded task-URL navigation and remains a
  visible fallback until selected-task verification is demonstrated. Ambiguous
  targets never pretend a guessed window is exact.
- **A desktop surface that gets out of the way.** The global Bar and detached
  Stoves can move and resize freely. Dense workloads wrap into responsive
  Benches without horizontal or vertical scrollbars, and detached windows share
  the same lightweight visual language.
- **Lifecycle you can trust.** Only reliable structured Cooking progress uses a
  partial arc. Needs Human, Cooked, Failed, and Disconnected use complete rings;
  disconnection never becomes completion. Internal subagent events no longer
  flood the Bar with duplicate Stoves.
- **Pins and Archive.** Pin work beyond the two-day freshness window, archive
  expired or manually removed sessions, and restore accidental removals without
  modifying the original Harness Session.
- **Local notifications.** Choose sound, system banner, Bar flash, and desktop
  attention. Sound is the only default. Cooked flashing can remain active until
  you click that Stove; temporary error messages disappear after 20 seconds.
- **Outbound status delivery.** Telegram, Slack, Discord, Lark/Feishu, and
  Generic Webhook remain send-only. There is no inbound listener or remote
  control path.
- **Four interface languages.** System, English, Simplified Chinese, Japanese,
  and Korean selection covers the main Bar, Settings, tray, window titles, and
  native notification copy.
- **SSH remains read-only.** Use zero-install discovery or an optional
  checksum-verified single-file Bridge over SSH stdin/stdout. Neither mode opens
  a port, stores an SSH password, or controls an Agent.
- **A better open-source front door.** The four READMEs now document the product
  model, architecture, privacy boundary, Adapter contract, evidence gaps, and a
  dedicated contract for Agents contributing to Cookbench. The repository also
  includes 13 editable HTML showcase pages and matching Chinese social images.

## Measured Footprint

On the recorded Apple M4/macOS arm64 host, the release app bundle occupied about
18 MiB on disk and the idle desktop process measured about 90 MiB RSS with 0.0%
sampled CPU. These are host-specific measurements, not universal platform
guarantees. See
[`docs/verification/performance-macos.md`](https://github.com/finitein/cookbench/blob/v0.3.0/docs/verification/performance-macos.md)
for the commands, conditions, and remaining Windows/Ubuntu gaps.

## Install

macOS universal or graphical Ubuntu/Linux x86_64:

```bash
curl -fsSL https://github.com/finitein/cookbench/releases/download/v0.3.0/install.sh | COOKBENCH_VERSION=v0.3.0 COOKBENCH_ALLOW_PRERELEASE=1 bash
```

Windows x64 PowerShell:

```powershell
$env:COOKBENCH_VERSION='v0.3.0'; $env:COOKBENCH_ALLOW_PRERELEASE='1'; irm https://github.com/finitein/cookbench/releases/download/v0.3.0/install.ps1 | iex
```

The bootstrap reads `release-manifest.json`, selects the matching artifact, and
verifies its SHA-256 digest before installation. Preview installation is
explicitly opt-in. See [`docs/installing.md`](https://github.com/finitein/cookbench/blob/v0.3.0/docs/installing.md) for dry-run,
source-build, runtime, SSH, and removal details.

## Platform Reality

- Automated package jobs build and audit macOS universal App/DMG, Windows x64
  MSI, and Ubuntu x64 DEB/AppImage artifacts.
- Recorded native evidence covers macOS and Ubuntu X11.
- Windows graphical launch, GNOME Wayland, exact focus across every terminal,
  multi-monitor restoration, live SSH transport, native notification centers,
  and real provider sandboxes retain explicit manual verification gaps.
- Homebrew, winget, and APT registry publication is not live yet.

The full, honest release evidence is maintained in the
[`17-point release checklist`](https://github.com/finitein/cookbench/blob/v0.3.0/docs/verification/release-checklist.md).

## Security Boundary

Native Session files remain authoritative. Cookbench stores bounded display
state, settings, pins, archive records, and minimum return locators in atomic
JSON. It has no SQLite transcript database, copies no complete conversation,
collects no telemetry, and does not start, stop, prompt, approve, host, or
control Agents.

Read [`docs/security.md`](https://github.com/finitein/cookbench/blob/v0.3.0/docs/security.md),
[`docs/privacy.md`](https://github.com/finitein/cookbench/blob/v0.3.0/docs/privacy.md), and the canonical
[`Harness compatibility matrix`](https://github.com/finitein/cookbench/blob/v0.3.0/docs/harness-compatibility.md)
before extending an Adapter.
