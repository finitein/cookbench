# Cookbench v0.4.2

Cookbench v0.4.2 fixes Global Bar top docking on macOS while retaining the
v0.4.1 WindowServer safety rollback for the dynamic status Stove.

## What Changed

- **Top docking now visibly auto-hides on macOS.** AppKit constrains visible
  windows to the screen, so the former negative-y move left the complete Bar at
  the top edge. Cookbench now shrinks the native window to the promised
  three-pixel trigger strip and restores its saved height on reveal.
- **The trigger no longer bounces open.** A pointer entry caused by the collapse
  itself is ignored until the pointer has left, while a later move to the top
  still reveals the Bar immediately.
- **Collapsed geometry is not saved as the user's preferred Bar size.** Native
  resize and minimum-size synchronization pause while the trigger is collapsed
  and resume when it expands.
- **The macOS status Stove remains suspended.** v0.4.2 keeps the static v0.3-era
  tray path restored by v0.4.1; it does not reconnect the WindowServer-sensitive
  dynamic status rendering path.

## Install

v0.4.2 remains an unsigned prerelease and must be selected explicitly:

```bash
curl -fsSL https://github.com/finitein/cookbench/releases/download/v0.4.2/install.sh | COOKBENCH_VERSION=v0.4.2 COOKBENCH_ALLOW_PRERELEASE=1 bash
```

```powershell
$env:COOKBENCH_VERSION='v0.4.2'; $env:COOKBENCH_ALLOW_PRERELEASE='1'; irm https://github.com/finitein/cookbench/releases/download/v0.4.2/install.ps1 | iex
```

## Safety And Verification

The fix was exercised on the affected Apple Silicon Mac in the same mirrored
dual-display configuration. The packaged WindowServer-sensitive status path
remains disconnected. Native geometry inspection confirmed a 281x98 Bar
collapsed to 281x3 at the top work-area edge and returned to 281x98 when the
pointer entered the trigger, without a WindowServer or application crash.
