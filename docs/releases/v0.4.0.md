# Cookbench v0.4.0

Cookbench v0.4.0 makes its lightest desktop surfaces more useful while keeping
the product in its existing lane: an observation and presentation layer for
coding-agent sessions, not an Agent host or control plane.

> This is an **unsigned prerelease candidate**. The source and local universal
> macOS package gates pass, while public artifacts, checksums, the release
> manifest, GitHub Actions publication, and signing evidence remain pending.

## Highlights

- **Minimal Bar.** Minimal mode shows one real Stove: the highest-priority
  canonical attention target changes automatically as session state changes.
  Full mode remains available when the complete Bar is needed.
- **Top docking for the Global Bar.** The Global Bar snaps within 12 px of the
  top edge, undocks after 24 px, and auto-hides after 600 ms while retaining a
  3 px trigger. This is presentation-only and does not affect detached Stoves.
  Wayland behavior is best effort.
- **macOS status Stoves.** Configure zero to eight visible slots (default
  three); the menu keeps stable priority slots, left click returns to the exact
  Stove, and right click lists every Stove.

## Install

macOS universal or graphical Ubuntu/Linux x86_64:

```bash
curl -fsSL https://github.com/finitein/cookbench/releases/download/v0.4.0/install.sh | COOKBENCH_VERSION=v0.4.0 COOKBENCH_ALLOW_PRERELEASE=1 bash
```

Windows x64 PowerShell:

```powershell
$env:COOKBENCH_VERSION='v0.4.0'; $env:COOKBENCH_ALLOW_PRERELEASE='1'; irm https://github.com/finitein/cookbench/releases/download/v0.4.0/install.ps1 | iex
```

These commands are the intended opt-in preview commands. They become usable
only when the corresponding prerelease artifacts are published. The bootstrap
will read `release-manifest.json`, select a matching artifact, and verify its
SHA-256 digest before installing. Homebrew, winget, and APT publication are not
live; see [`docs/installing.md`](../installing.md) for current registry status,
dry-run behavior, source builds, SSH, and removal.

## Verification Status

The 2026-09-02 release-candidate run passed `./scripts/verify.sh`, including
Rust formatting, Clippy with warnings denied, all workspace tests and build,
TypeScript, 155 Vitest tests, three GNOME protocol tests, 23 Playwright flows,
production build isolation, and source-package audit. A local universal macOS
App and DMG also passed package smoke, launched as version `0.4.0`, and rendered
the default three-Stove status item at Retina scale. No GitHub Actions package
run, published artifact hashes, or public release is claimed yet.

The remaining native checks are intentionally explicit:

- Windows, X11, and Wayland live dock behavior, with Wayland treated as best
  effort rather than a full overlay guarantee.
- Broader packaged macOS status-item checks for variable-width slot edges,
  VoiceOver, light/dark appearance, fullscreen, and multi-monitor behavior.
- Five production-emission persistence tests use Tauri's mock runtime and run
  on macOS/Linux only because of upstream
  [`tauri-apps/tauri#13419`](https://github.com/tauri-apps/tauri/issues/13419);
  platform-neutral persistence coverage remains enabled on Windows.
- Stable signing and notarization eligibility before any signed stable claim.

See the [`v0.4.0 release candidate checklist`](../verification/release-checklist.md)
for the full evidence ledger.

## Privacy and Control Boundary

Native Harness Session files remain authoritative. Cookbench stores bounded
display state, settings, pins, archive records, and minimum return locators;
it does not copy full conversations or maintain a SQLite transcript database.
Cookbench does not prompt, approve, start, stop, host, or otherwise control an
Agent. SSH observation remains read-only, and outbound integrations do not
accept inbound remote-control commands.
